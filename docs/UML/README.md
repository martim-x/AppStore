# Как чертить схемы draw.io для этого проекта

Практические правила, выведенные на реальных ошибках: сначала схема получалась с
наложением текста и линиями сквозь блоки. Ниже — как делать правильно.

## 1. Файл и структура

- Обычно один файл содержит одну страницу `<diagram>` внутри `<mxfile>`. Исключение в этом проекте: `class_diagram.drawio` имеет основную страницу и дополнительную страницу свободных блоков.
- Каждая страница имеет отдельную `<mxGraphModel>` с `gridSize=10`; несколько страниц допустимы, когда это нужно для ручной компоновки.
- Все вершины и рёбра — прямые дети слоя `parent="1"`, кроме строк таблиц/классов
  (они — дети своей swimlane, см. п. 3).

## 2. Никогда не пиши многострочный текст в одну ячейку

Главная ошибка: `value="MainViewModel&#10;- IRepository _repo&#10;..."` в одной
swimlane. Draw.io рисует весь текст в заголовке (`startSize`), строки наезжают
друг на друга и на рамку.

Правильно — swimlane только для заголовка, каждая строка отдельной ячейкой:

```xml
<mxCell id="c1" value="MainViewModel : ViewModelBase"
        style="shape=swimlane;html=1;startSize=30;fillColor=none;strokeColor=#000000;fontSize=13;align=left;"
        vertex="1" parent="1">
  <mxGeometry x="20" y="110" width="250" height="144" as="geometry"/>
</mxCell>
<mxCell id="c2" value="- IRepository _repo"
        style="text;html=1;align=left;verticalAlign=middle;spacingLeft=6;fontSize=13;strokeColor=none;fillColor=none;whiteSpace=nowrap;"
        vertex="1" parent="c1">
  <mxGeometry x="0" y="30" width="250" height="19" as="geometry"/>
</mxCell>
```

Высота блока: `30 + 19 * число_строк`. Строки: `y = 30 + 19 * i`, высота `19`.

## 3. Экранирование угловых скобок

`html=1` съедает `<App>` как HTML-тег — в PNG остаётся «List GetAllApps()».
Нужно двойное экранирование: в модели писать `&amp;lt;App&amp;gt;`, тогда после
разбора XML остаётся `&lt;App&gt;`, и на картинке видно `List<App>`.

## 4. Связи

- Всегда задавай точки выхода/входа, иначе линия идёт через блоки:
  `exitX=0.5;exitY=1;exitDx=0;exitDy=0;entryX=0.5;entryY=0;entryDx=0;entryDy=0;`
- Ортогональные маршруты: `edgeStyle=orthogonalEdgeStyle;rounded=0;`.
- Наследование — `endArrow=block;endFill=0;` (полый треугольник).
- Реализация интерфейса — то же плюс `dashed=1`.
- Зависимость — `endArrow=open;dashed=1;`.
- Направленная ассоциация — сплошная открытая стрелка `endArrow=open;`.
- Не подписывай связи словами «наследует»/«implements» — подписи наезжают на
  блоки; тип связи виден по наконечнику.
- Соединяй только соседние блоки: связь через две колонки почти всегда проходит
  сквозь промежуточные классы.

## 5. Компоновка

- Колонки: ширина 240–250, зазор 30–40. Композиция по ширине ≤ 1100 единиц.
- Шрифт в PDF ≈ `fontSize × 453 / ширина_композиции_в_единицах` pt. При 1100 ед
  и `fontSize=13` это ≈ 5.4 pt — предел; больше классов на A4 не влезает.
- Используй `ST_IFACE` для интерфейсов, `ST_CLASS` для классов, стереотип
  `«interface»` в заголовке.
- В завершённых архитектурных схемах не оставляй пустых блоков-заглушек. Исключение по просьбе владельца: на дополнительной странице `class_diagram.drawio` оставлены title-only блоки для ручной компоновки; их содержимое и связи владелец добавит самостоятельно.

## 6. Диаграмма последовательности

- Линии жизни: `shape=umlLifeline`, шаг между сообщениями 45–50 px, иначе
  подписи сливаются.
- Вызов — сплошная стрелка, возврат — пунктир (`dashed=1`).
- Самовызов: петля `source(sx,y) → (sx+45,y) → (sx+45,y+26) → target(sx,y+26)`,
  возврат на ту же линию жизни.
- Подпись сообщения — `verticalAlign=bottom`, шрифт 12–13.

## 7. Экспорт

```
draw.io.exe --export --format png --scale 2.5 --border 20 --output out.png in.drawio
```

`--scale 2.5` даёт запас для печати, `--border 20` — чтобы подписи не липли к
краю кадра.

## 8. Что генератор НЕ трогает

`use_case.drawio` и `erd.drawio` ведутся вручную: они проверены и приняты.
`scripts/diagrams/make_diagrams.py` генерирует только `class_diagram.drawio` и
`sequence_diagram.drawio` — не добавляй их обратно в `BUILDERS`, иначе ручные
схемы затираются (так уже случилось однажды, восстанавливали из git).

## 9. Проверка перед вставкой в отчёт

1. Экспортировать PNG.
2. Уменьшить копию до ~900 px и посмотреть глазами: наложения строк, обрезка
   текста, линии сквозь блоки.
3. Проверить, что подпись рисунка стоит на той же странице, что и рисунок
   (в отчёте ширина `width_cm` подбирается так, чтобы высота + подпись влезали:
   для ERD с пропорцией 1.3 ширина 11 см, для квадратных схем — 14–16 см).
